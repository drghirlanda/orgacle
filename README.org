#+TITLE: Orgacle
#+AUTHOR: Stefano Ghirlanda

/Presentation mode for Emacs Org-mode/

Orgacle began as a fork of [[https://github.com/dakrone/epresent][epresent]], by Tom Tromey, Phil Hagelberg, Eric
Schulte, Puneeth Chaganti and Lee Hinman, unmaintained since 2016.

* Installation

Orgacle is not on MELPA yet. Until it is, clone the repository and put it on
your =load-path=:

#+begin_src emacs-lisp
  (add-to-list 'load-path "/path/to/orgacle")
  (require 'orgacle)
#+end_src

It needs Emacs 29.1 or later and Org 9.6 or later, and nothing else. Two
optional packages improve it if you already have them: =org-superstar=
prettifies bullets, and =pdf-tools= lets a multi-page PDF be advanced beside a
slide.

** Starting a presentation

Run =M-x orgacle-run= in an Org buffer.  Earlier versions bound this to
=F5= in every Org buffer; a package may not claim a user's function keys,
so bind it yourself if you want it back:

#+begin_src emacs-lisp
  (with-eval-after-load 'org
    (define-key org-mode-map (kbd "<f5>") #'orgacle-run))
#+end_src

* Breaking changes

- =F5= no longer starts a presentation by itself. Bind it yourself if
  you want it back; see the snippet under "Starting a presentation"
  above.
- =orgacle-tooltip-mode= is now a boolean. Setting it to =0= used to
  disable tooltips; it now *enables* them, because =0= is non-nil in
  Emacs Lisp. Use =nil= to disable tooltips.
- The package is now called =orgacle=. Every command, variable and face
  is renamed from =epresent-...= to =orgacle-...=, and Org properties
  from =EPRESENT_...= to =ORGACLE_...=.
- Run =M-x orgacle-migrate-buffer= on an existing presentation to
  convert its properties, or =M-x orgacle-migrate-file= on a file.
- Settings in your init file need renaming by hand: =orgacle-migrate-buffer=
  converts presentation documents, not Emacs configuration. A
  =(setq epresent-slide-in t)= becomes =(setq orgacle-slide-in t)=.
- =N= and =P=, during a presentation, are now incremental reveal's own keys
  (=orgacle-reveal-next= and =orgacle-reveal-previous=) instead of the old
  folded-subheading commands. An =:ORGACLE_STEPWISE:= deck keeps presenting
  with no changes needed, but its behaviour changes more than "accordion
  versus cumulative" suggests: the old mechanism never actually hid anything
  on the way in, so a STEPWISE slide appeared fully visible; the new one
  starts a STEPWISE slide fully *hidden*, needing =N= presses to reveal
  anything at all — see "Revealing a slide piece by piece" below, which
  spells out exactly what changes. The old
  commands, =orgacle-next-subheading= and =orgacle-previous-subheading=, are
  still defined for anyone who rebinds =N=/=P= back to them.
- =orgacle-goto-top-level= is removed. It predated the navigation rewrite,
  had no key of its own in =orgacle-mode-map=, and disagreed with the model
  navigation was rewritten around: it would treat a hidden or title-page
  heading as a valid destination, when no other command in the package ever
  presents one as a slide. If you had bound it yourself, rebind to plain
  Org's own =org-up-heading-safe= instead — the closest built-in equivalent,
  though it is not frame-level-aware the way the removed command was.

* Basic usage

- Call =orgacle-run= on an org-buffer.
- Press =t= or =1= to view the top level of the presentation
- Navigate the presentation with =n/f=, =p/b=
- Go to a specific page with =v <num> RET=
- Scroll with =j= and =k=
- Working with code blocks:
  - =c= and =C= to navigate between code blocks
  - =e= to edit a code block
  - =x= to run it
  - =s= or =S= to toggle code block visibility
- Use =i= to split the window and load a file in the new window (see
  below).
- Use =I= to show a video fullscreen (see below).
- Use =N= and =P= to reveal subheadings one at a time (see [[The basics]])
- Press =E= to edit the slide text in place, =C-c C-c= to stop editing
- Press =+= and =-= to grow and shrink the font
- Press =m= to toggle the mouse pointer's visibility
- Press =r= or =g= to re-render the slide, =R= to force a full redisplay
- Quit with =q=

* Manual

Everything below is optional. A plain Org file with a few headings presents
correctly with no properties, no keywords and no configuration; the features
here are for when you want more than that.

** The basics

Orgacle presents the buffer you are already in. Nothing is exported or
converted: =M-x orgacle-run= takes the current Org buffer, opens a
full-screen frame, and shows it a slide at a time.

*** What becomes a slide

By default every top-level heading is one slide. Change that per file with a
keyword at the top of the buffer:

#+begin_src org :eval no
  ,#+ORGACLE_FRAME_LEVEL: 2
#+end_src

With that, each second-level heading is a slide and first-level headings group
them. Text before the first heading is shown as a table of contents.

Three kinds of subtree are treated specially:

- A heading named =Title page= is skipped when navigating. Use it for notes
  you want to read before you start.
- A heading named =Speaker notes= is hidden from the slide and collected into
  the notes buffer instead. See [[Speaker notes]].
- Any heading with an =ORGACLE_HIDE= property is hidden from the slide.

*Known issue, affecting =Speaker notes= and =ORGACLE_HIDE= subtrees:*
pressing =r=, =g=, or =x= on a slide, editing a source block on it with
=e= and exiting, or exiting text-edit mode with =E= then =C-c C-c=, can
un-hide one of these subtrees on the presentation screen itself — a
private-notes leak to the audience for =Speaker notes= in particular.
The exposure is permanent, not limited to the slide it happened on:
navigating away and back, or returning to the first slide with =t=,
does not re-hide it, because the overlay that hides these subtrees is
built once, when the presentation starts, and none of these commands
rebuilds it — quitting and re-running the presentation is the only way
back to a hidden state. The exact rule for whether a subtree is at
risk: it stays hidden only when the subtree, *including any children of
its own*, is the last subtree of its slide, with another top-level
slide heading immediately following. Plain trailing text still inside
the subtree's own body is fine, and so are the subtree's own children
— what breaks it is a *sibling* heading after it on the same slide, or
the subtree being the deck's actual last heading with nothing following
at all. Until this is fixed, avoid pressing =r=, =g=, =x=, or editing
text or code, on any slide with a =Speaker notes= or =ORGACLE_HIDE=
subtree that is not immediately followed by another slide.

=Title page= is exempt from this in its documented use, as a heading of
its own at the slide level: such a heading is never itself a slide, so
it is never the one the presentation gets narrowed to, and the leak
above only ever exposes a subtree that lies inside the slide currently
on screen. Used instead as a subheading *inside* a slide — not how this
README documents it — a =Title page= heading is at exactly the same
risk as =Speaker notes= or =ORGACLE_HIDE=, by the same rule.

*** Navigating

Once presenting, =n=, =f=, =SPC=, =→= and =PageDown= go forward; =p=, =b=,
=←=, =PageUp= and =Backspace= go back. =t= or =1= returns to the first slide,
and =v= asks for a slide number. =j= and =k= scroll within a slide that is
taller than the screen. =q= ends the presentation and restores the Org buffer
as it was.

The mode line shows the slide number. Set =orgacle-mode-line= to nil to hide
it, or to any mode-line construct to show something else; a single file can
override it with =#+ORGACLE_MODE_LINE:=.

*** Talk timer

Nothing about a timer appears anywhere -- not in the mode line, not in the
presenter console (see [[Speaker notes]]) -- until a target duration is set.
Give the talk a length, in minutes, and both places start showing elapsed
time against it:

#+begin_src org :eval no
  ,#+ORGACLE_DURATION: 20
#+end_src

=orgacle-duration= (default nil) sets the target for every file; a single
file overrides it with =#+ORGACLE_DURATION:=. With neither set, the mode
line shows only the slide number, exactly as if the feature did not exist.
=#+ORGACLE_DURATION:= takes a whole number of minutes. A value that is not
a whole positive number -- an empty or whitespace-only value, =twenty=,
=1,5=, =2x=, =0=, a negative number, or a number with a decimal point such
as =1.5= (unlike =:ORGACLE_TEXT_SCALE:=, a decimal point means nothing
here) -- is treated exactly like the keyword being absent, falling back to
=orgacle-duration=, rather than showing a broken or permanently-overrun
timer. Once a target is set, =MM:SS/MM:SS= -- elapsed over target -- appears
next to the slide number, changing to =orgacle-timer-warning-face= once elapsed
time reaches 90% of the target and to =orgacle-timer-overtime-face= once it
reaches the target itself, so overrunning is visible at a glance rather than
something the presenter has to do arithmetic to notice. Minutes are not
wrapped at 60: a 75-minute talk reads =75:00=, not =1:15:00=, since the
number a presenter actually wants mid-talk is minutes elapsed.

*** Revealing a slide piece by piece

Give a slide an =:ORGACLE_REVEAL:= property and it starts with its targets
hidden, revealing them one at a time as you present. The property's value
picks what counts as a target: =items= for its top-level list items, =headings=
for its direct subheadings.

#+begin_src org :eval no
  ,* Three things
    :PROPERTIES:
    :ORGACLE_REVEAL: headings
    :END:

  ,** First
  ,** Second
  ,** Third
#+end_src

=N= and =P= always drive the reveal, on any slide, regardless of the option
below. With =orgacle-reveal-on-navigation= at its default of =t=, =n= and =p=
drive it too, but they hand off to ordinary navigation at different points,
not a shared "still mid-reveal" state: while the current slide still has
something hidden, =n= reveals the next target instead of moving to the next
slide; once nothing is left hidden -- everything already revealed, or no
=:ORGACLE_REVEAL:= property at all -- =n= changes slide exactly as it always
has. =p= mirrors this around what is *revealed*, not what is hidden: whenever
the current slide has something revealed, =p= hides the last-revealed target
again instead of moving to the previous slide -- and a fully-revealed slide
still has everything revealed, so =p= there re-hides one target per press,
the same number of presses =N= took to reveal them, before it actually
leaves the slide. Only once nothing is left revealed -- the slide still at
its fully-hidden starting state, or no =:ORGACLE_REVEAL:= property at all --
does =p= change slide immediately. Set =orgacle-reveal-on-navigation= to
=nil= to turn all of this off and keep =n=/=p= strictly for changing slides,
with reveal reachable only on =N=/=P=.

Moving forward onto a slide — the first time, or by jumping to it with =v= —
always shows it fully hidden, needing =N= or =n= presses to see anything.
Stepping backward onto it with =p=, though, lands it fully revealed instead,
matching Beamer and reveal.js: the point of stepping back across a slide
boundary is to see what was already shown a moment ago, not to present it
again from scratch.

=:ORGACLE_STEPWISE:= still works, as an alias for =:ORGACLE_REVEAL: headings= —
you do not need to rename an existing property to keep a STEPWISE deck
presenting. *Its behaviour has changed*, though, more than a first glance at
"accordion versus cumulative" suggests, so read this carefully if you have an
existing STEPWISE deck. At the default =orgacle-frame-level= of 1, the old
=ORGACLE_STEPWISE= never actually hid anything on the way in: a slide with the
property appeared with every subheading and its content already fully
visible, exactly like a slide without the property; =N=
(=orgacle-next-subheading=) only moved point forward, silently failing to hide
anything because of how it checked the property (a level test that never
matched the slide's own heading at level 1, and a lookup that does not
inherit down to the subheadings themselves); only =P=
(=orgacle-previous-subheading=), pressed enough times, progressively hid
subtrees on the way back out. This is the common case and the one the old
README described, but not the only one: with =#+ORGACLE_FRAME_LEVEL: 2= or
deeper, the slide heading itself sits at level 2 or below, so that same level
test *does* pass on the slide heading, and =N= did fire =outline-hide-subtree=
there, hiding the whole subtree — some real, working accordion behaviour that
a deck using a non-default frame level actually relied on. Either way, the new
mechanism starts a slide with =:ORGACLE_STEPWISE:= *fully hidden* and needs =N=
presses to reveal anything at all, cumulatively — once a heading is revealed
it stays visible as you reveal more, alongside it. A presenter who reads only
"one at a time, now cumulative" will not anticipate walking onto an
empty-looking slide; the honest summary is: what used to show everything
immediately (at the default frame level) now shows nothing until you press
=N=.
=orgacle-next-subheading= and =orgacle-previous-subheading=, the functions that
used to implement the old behaviour, are still defined and still work exactly
as before if you call them directly or rebind =N=/=P= back to them yourself;
they are simply no longer bound by default.

*** Size and appearance

=orgacle-text-scale= (default 400) sets the base font height, and =+= and =-=
adjust it during a presentation. TODO keywords, tags and property drawers are
hidden by default — see =orgacle-hide-todos=, =orgacle-hide-tags= and
=orgacle-hide-properties=. Bullets are prettified with =org-superstar= when
that package is installed; set =orgacle-use-org-superstar= to nil if you would
rather they were not. Orgacle works without =org-superstar= installed.

A slide can override the base font height, and the frame's background
colour, just for itself, with =:ORGACLE_TEXT_SCALE:= and
=:ORGACLE_BACKGROUND:=. Both reset automatically on the next slide, whether
or not that slide sets its own — a slide with neither property always looks
exactly like the deck's default, even right after one that set both.

#+begin_src org :eval no
  ,* A slide that stands out
    :PROPERTIES:
    :ORGACLE_TEXT_SCALE: 1.5
    :ORGACLE_BACKGROUND: midnightblue
    :END:
#+end_src

=:ORGACLE_TEXT_SCALE:= takes a number, read the same way =orgacle-text-scale=
itself is: a whole number such as =600= is an absolute height in tenths of a
point, and a number with a decimal point such as =1.5= is a scale factor
applied to whatever height the slide would otherwise have — =1.5= for 150%,
=0.7= for 70%. =:ORGACLE_BACKGROUND:= takes any colour Emacs recognizes, by
name (=midnightblue=, =red=, …) or as =#rrggbb=. A value that is not a
positive number, or not a colour Emacs recognizes, is treated exactly like
the property being absent — a presenter's typo shows the deck's ordinary
appearance rather than breaking the slide or the talk.

=:ORGACLE_BACKGROUND:= sets a frame parameter, so it only does anything once
a presentation is actually on screen in its own frame; nothing in a plain
Org buffer, or before =orgacle-run= has created that frame, is affected by
it. =:ORGACLE_TEXT_SCALE:= has no such restriction.

*** Editing during a presentation

=E= makes the slide editable in place, with the cursor visible; =C-c C-c=
stops editing and refreshes. =r= or =g= re-renders the current slide, which is
useful after changing something outside the presentation. =R= forces a full
redisplay if the screen is left dirty by an external program.

** Inline images

Images linked from the buffer are displayed inline, and are regenerated when a
slide is shown, so an image produced by a code block appears as soon as the
block runs.

#+begin_src org :eval no
  [[file:diagram.png]]
#+end_src

Use =#+attr_org: :width ...= to control the displayed size; Orgacle keeps
=attr_org= lines out of the slide while honouring them.

LaTeX fragments are rendered as images too, at a scale set by
=orgacle-format-latex-scale= (default 4, chosen so formulas match the enlarged
presentation font rather than the size they would be in an ordinary buffer).

** Code blocks

Source blocks are shown with syntax highlighting and can be run in front of an
audience.

- =c= and =C= move between blocks on the slide, flashing the cursor so the
  audience can see which one has focus.
- =x= runs the block under point. Results appear on the slide, and the slide
  re-renders automatically, so a block producing an image shows the image.
- =e= opens the block in an ordinary Org source-editing buffer, with a normal
  cursor. =C-c '= returns.
- =s= hides or shows every block on the slide; =S= does the same for the block
  under point. This is useful for showing a result first and the code that
  produced it second.

Set =orgacle-src-blocks-visible= to nil to have blocks start hidden on each
slide, so =s= reveals them.

** Showing another file

It is sometimes useful to show an additional file. This could be done
with the usual Emacs commands, but sometimes a more "polished" look is
desirable in a presentation. Orgacle supports splitting the window to
show a file in a new buffer. This functionality is activated by the
=i= key during the presentation, and it can be tested invoking =M-x
orgacle-show-file= outside of the presentation. The filename is set
through the property =ORGACLE_SHOW_FILE= and the file is showed by default
to the right of the presentation buffer. It can be shown under the
presentation by setting the property =ORGACLE_SHOW_BELOW= to a
non-nil value.

Here is an example:

#+begin_src org :eval no
    * My slide
      :PROPERTIES:
      :ORGACLE_SHOW_FILE: myfigure.pdf
      :ORGACLE_SHOW_BELOW: t
      :END:
#+end_src

Any file that can be opened in Emacs can be shown in this way. For
example, a PDF with multiple pages can be used to show more than one
figure in a sequence.


*** Videos

=I= plays a video full screen, leaving the presentation frame and returning to
it when the player exits. The filename comes from an =ORGACLE_SHOW_VIDEO=
property, and an =ORGACLE_MUTE= property plays it silently:

#+begin_src org :eval no
  ,* A demonstration
    :PROPERTIES:
    :ORGACLE_SHOW_VIDEO: demo.mp4
    :ORGACLE_MUTE: t
    :END:
#+end_src

=orgacle-video-player= selects the player: =mplayer= (the default) or =vlc=.
The player must be installed and on your =PATH=.

*** Sizing and automatic display

=ORGACLE_SHOW_SIZE= sets the size of the auxiliary window, in lines when the
file is shown below and columns when it is shown beside. Without it the window
is split evenly.

=ORGACLE_SHOW_AUTO= shows the file as soon as the slide appears, rather than
waiting for =i=.

For PDFs and images the file is fitted to the window: to width when beside the
slide, to height when below. With =pdf-tools= installed a multi-page PDF opens
at page one and =i= advances it a page at a time without leaving the
presentation, so a sequence of figures needs one property and one key.

** Indicators

During a presentation the right fringe shows what the current slide can
display, so you know what is available without remembering:

- a *filled square* — the slide has an =ORGACLE_SHOW_FILE=, so =i= will show it
- a *hollow square* — the slide has an =ORGACLE_SHOW_VIDEO=, so =I= will play it
- a *right arrow* — the PDF beside the slide has more pages, so =i= advances it

A slide whose file is shown automatically via =ORGACLE_SHOW_AUTO= gets no
indicator, since there is nothing left to press. Set =orgacle-indicators= to
nil to turn all of them off.

** Speaker notes

Give any slide a subheading named exactly =Speaker notes= and its contents are
kept off the slide and collected into a separate =*Orgacle Notes*= buffer,
shown in its own frame when the presentation starts. Move that frame to a
second screen and it follows along, showing the notes for the slide you are on.

#+begin_src org :eval no
  ,* What the data show
    Sales rose in every region.

  ,** Speaker notes
     Do not read the numbers aloud; the audience can see them.
     Mention the Chicago outlier only if someone asks.
#+end_src

Two details worth knowing:

- The heading must be spelled =Speaker notes= for the notes to be *collected*.
  Other capitalisations are still hidden from the slide, but their contents
  will not reach the notes buffer.
- Set =orgacle-speaker-notes= to nil to skip the notes frame entirely.
- *Known issue:* see the private-notes leak warning under [[What becomes a
  slide]] — =Speaker notes= is the subtree kind where this matters most,
  since a leak here exposes your own notes to the audience, not just a
  hidden property.

=M-x orgacle-estimate-time= reports how long it would take to read all your
speaker notes aloud, together with the word count, which is a reasonable proxy
for how long the talk will run. It assumes 150 words per minute; change that
with =orgacle-wpm=. It is not bound to a key, since you want it while writing
rather than while presenting.

*** Presenter console

With =orgacle-presenter-view= at its default of =t=, the notes buffer doubles
as a presenter console: a header line above the notes text shows the current
slide's position as =N/M=, the next slide's title, and the talk timer (see
[[Talk timer]]) -- each segment separated from its neighbours by two spaces
and simply omitted, with no separator left dangling in its place, when it has
nothing to contribute: no "next" segment on the last slide, no timer segment
at all with no target duration configured. Set =orgacle-presenter-view= to
nil to leave the notes buffer exactly as it was before this existed, with no
header line at all; it also has no effect when =orgacle-speaker-notes= is
nil, since there is then no notes buffer for a header to appear in.

** Slide-in effect

Slides can slide up into place instead of appearing at once. It is off by
default:

#+begin_src emacs-lisp :eval no
  (setq orgacle-slide-in t)
#+end_src

Individual slides override the setting with an =ORGACLE_SLIDE_IN= property:
=no=, =nil= or =off= turns the animation off for that slide, and any other
value turns it on. So you can leave it off globally and animate one slide, or
leave it on and exempt a slide that has to appear instantly.

The heading stays where it is and the body rises into place beneath it. Three
variables shape the movement: =orgacle-slide-in-lines= (how far the body
travels, default 10), =orgacle-slide-in-duration= (how long the whole movement
takes in seconds, default 0.25) and =orgacle-slide-in-pause= (a wait inserted
just after it starts, default 1 second), which holds the heading alone on
screen for a moment before the rest arrives.

** 'Laser pointer' effect

During a presentation the mouse pointer becomes a dot, which reads as a laser
pointer when you are pointing at something on a projector. Choose a different
shape with =orgacle-x-pointer-shape=, which takes any of Emacs's =x-pointer-=
constants.

=m= toggles the pointer's visibility: press it to hide the pointer when it is
in the way, press it again to bring it back. Moving the mouse does not bring
it back by itself. Quitting the presentation restores your normal pointer.

This is an X11 feature. On a Wayland, macOS or Windows build, and in a terminal,
the pointer is left alone and =m= does nothing. Orgacle detects this and stays
quiet rather than failing.

Tooltips are suppressed during a presentation so a stray hover cannot pop
something up on the projector; set =orgacle-tooltip-mode= to t if you want them.

The 75-pixel border around the presented material comes from
=orgacle-internal-border-width=; change it to taste. It is passed straight
through to the presentation frame when that frame is created, so a change
takes effect on the next presentation, not the one already running.

** Extending Orgacle: orgacle-page-hook

Every time a slide is displayed and narrowed, Orgacle runs =orgacle-page-hook=.
This is how the built-in features hook into slide display — per-slide
appearance, incremental reveal, showing an auto-display file, the slide-in
effect, the fringe indicators and the speaker notes are each just a function
on this hook — and it is also the supported way to add your own behaviour
without editing Orgacle itself:

#+begin_src emacs-lisp :eval no
  (add-hook 'orgacle-page-hook #'my-function)
#+end_src

A few things to know before adding to it:

- A member takes no arguments.
- Order matters. The built-in order is appearance, reveal, file, slide-in,
  indicators, then notes. Two orderings are real invariants, not just how
  things happen to be arranged: file-before-indicators, because showing a
  file clears the fringe overlays, so indicators drawn before it would be
  wiped a moment later; and appearance-and-reveal-before-slide-in, because
  the slide-in effect forces a real redisplay partway through itself, so
  anything not yet applied by then — an unrevealed target, the wrong text
  scale or background — would be visible to the audience for the length of
  the slide-in pause. Use the APPEND argument of =add-hook= to control where
  your function lands relative to the built-ins.
- A member that signals is logged and does not stop the rest of the hook, so a
  bug in one extension cannot end a presentation mid-talk.

* Customization

You can customize the variables described above and other affecting
how the presentation looks using =M-x customize-group [enter]
orgacle=.
