*Goal:* Put =epresent.el= under compile, lint, docstring and test gates that all
pass on Emacs 29.4, 30.2 and snapshot, and fix every defect that stands in the
way — without renaming anything.

*Architecture:* A =Makefile= drives four batch targets (=compile=, =checkdoc=,
=lint=, =test=) through a bootstrap file that provisions development
dependencies into =./.deps=, so the only tool a contributor needs is Emacs
itself. GitHub Actions runs the same =make= targets across the version matrix.
Characterization tests are written *before* =lexical-binding= is switched on,
because that switch changes the meaning of roughly forty =setq= sites.

*Tech stack:* Emacs Lisp, ERT, =checkdoc=, =package-lint=, GNU Make, GitHub
Actions.

* Global constraints

Copied verbatim from the design document; every task inherits them.

- Package stays named =epresent= for the whole of P0. The rename to =orgacle=
  is P1 and must not leak into this phase.
- Version floor: =Package-Requires: ((emacs "29.1") (org "9.6"))=.
- CI matrix: Emacs 29.4, 30.2, snapshot (all three exist in =nix-emacs-ci=).
- Nothing beyond Emacs and Org may be a hard requirement.
- Every file must byte-compile clean with =byte-compile-error-on-warn= set.
- No =[f5]=–=[f9]= binding may survive in any keymap the package defines, and
  the package must not modify =org-mode-map= at load time.
- Exit criteria for the phase: =make compile checkdoc lint test= green on all
  three Emacs versions.

* Amendments to the design document

Two changes to the spec, made while planning. Both are folded into the tasks
below; update =docs/superpowers/specs/2026-08-10-orgacle-design.org= to match.

1. *Obsolete Org APIs and the compat shims move from P2 into P0* (Tasks 10
   and 11). The spec's P0 exit criterion is a clean compile under
   =byte-compile-error-on-warn=, and on the snapshot Emacs the twelve obsolete
   calls are warnings — therefore errors. P0 cannot be green without them.
   P2 keeps the file split, the page hook, the session struct, and the runtime
   soft-dependency handling for =pdf-tools= and the video player.
2. *Build tool: GNU Make, not Eldev.* Eldev is not installed on this machine and
   is not packaged for Slackware. A 30-line =Makefile= plus a bootstrap file
   gives the same result, needs nothing but Emacs, and lets CI run byte-for-byte
   the same commands as a local checkout. The dependency provisioning Eldev
   would have done is eight lines of =package-install=.

* Defects discovered while planning

Found by reading during planning, beyond those already in the spec. All are
fixed in this phase; each is named in the task that fixes it.

- *=epresent-slide-in= is dead and the animation is always on.*
  =epresent-slide-in-effect= computes =slide-local= as t unless the heading's
  property is exactly ="no"=, computes =slide-global= from the defcustom, then
  tests =(or slide-local (and (not slide-global) slide-local))=, which reduces
  to =slide-local=. The global setting is never consulted. The animation
  therefore runs on every slide even though =epresent-slide-in= defaults to nil.
  Fixed in Task 9 — *this changes visible behaviour, see the note there.*
- *Speaking-time estimate truncates instead of rounding to the half minute.*
  =epresent-estimate-time= does =(/ (ceiling (* speaker-time 2)) 2)= — integer
  division, so 225 words at 150 wpm reports 1 minute, not 1.5. The comment
  above it says "round to the half minute". Fixed in Task 9.
- *=epresent-fontify= calls =(org-superstar-mode)= with no argument*, which
  toggles rather than enables. On a refresh it switches the bullets back off.
  Fixed in Task 11.
- *=epresent-next-page='s docstring inverts its own argument.* It says "If SKIP
  is nil, the page is advanced but not displayed"; the code is
  =(unless skip (epresent-current-page))=. Fixed in Task 9.
- *The LaTeX export backend emits nothing for its property drawers unless the
  user opts in.* =org-export-with-properties= defaults to nil, so the
  =property-drawer= translator — the entire point of the backend — never runs.
  Verified: exporting a fixture with =EPRESENT_SHOW_FILE= produces no
  =\includegraphics= at all unless =:with-properties t= is passed. Fixed in
  Task 9 by giving the derived backend its own default.
- *=epresent--collect-notes= emits the last heading twice.* The loop tests
  =(< (point) (point-max))= before calling =org-next-visible-heading=, so on the
  final heading the body runs once more with point unmoved. Verified: a
  three-slide fixture yields ="* Third slide"= twice. Characterized in Task 5
  and left standing — P3 replaces this loop with the slide vector.
- *=epresent-x-pointer-shape= is declared =:type 'symbol= but holds an integer*,
  and — far worse, discovered only when CI ran — its default is the bare symbol
  =x-pointer-dot=, which =defcustom= evaluates at load time and which exists
  only on X11 builds. The package fails to load outright on macOS, Windows,
  terminal and headless Emacs. Fixed in Task 3a, which was inserted for it.

Deferred deliberately to P3, not to be touched here: =epresent-quit= calls
=(kill-buffer (get-file-buffer epresent--org-file))= without checking that the
buffer exists, and =(kill-buffer nil)= kills the current buffer. It is reachable
only when presenting a narrowed region. P3 rewrites =epresent-quit= wholesale.

- [ ] *Step 1: Write the bootstrap*

Create =test/init.el=:

#+begin_src emacs-lisp :eval no
  ;;; init.el --- Batch bootstrap for the epresent test suite  -*- lexical-binding: t; -*-

  ;;; Commentary:

  ;; Loaded with -l before every batch target in the Makefile.  Provisions the
  ;; packages needed to lint and test epresent into ./.deps, so that `make'
  ;; needs nothing on the machine but Emacs itself, and puts the project root
  ;; on `load-path'.

  ;;; Code:

  (require 'package)
  (require 'seq)

  (defconst epresent-dev-dependencies '(package-lint)
    "Packages needed to lint and test epresent, but not to use it.")

  (setq package-user-dir (expand-file-name ".deps" default-directory)
        package-archives '(("gnu"   . "https://elpa.gnu.org/packages/")
                           ("melpa" . "https://melpa.org/packages/")))

  (package-initialize)

  (let ((missing (seq-remove #'package-installed-p epresent-dev-dependencies)))
    (when missing
      (package-refresh-contents)
      (mapc #'package-install missing)))

  (add-to-list 'load-path default-directory)

  (provide 'init)
  ;;; init.el ends here
#+end_src

- [ ] *Step 2: Write the checkdoc wrapper*

=checkdoc-file= prints complaints but never changes the exit status, so a
Makefile cannot tell a clean run from a dirty one. Create
=test/checkdoc-batch.el=:

#+begin_src emacs-lisp :eval no
  ;;; checkdoc-batch.el --- Fail the build on checkdoc complaints  -*- lexical-binding: t; -*-

  ;;; Commentary:

  ;; `checkdoc-file' prints its complaints but never changes the exit status,
  ;; so a Makefile or a CI job cannot tell a clean run from a dirty one.  This
  ;; wrapper counts complaints through `checkdoc-create-error-function' and
  ;; exits non-zero when there are any.
  ;;
  ;; Usage: emacs -Q --batch -l test/checkdoc-batch.el FILE...

  ;;; Code:

  (require 'checkdoc)

  (defvar epresent-checkdoc-count 0
    "Number of complaints seen during this batch run.")

  (setq checkdoc-create-error-function
        (lambda (text start _end &optional _unfixable)
          (setq epresent-checkdoc-count (1+ epresent-checkdoc-count))
          (message "%s:%d: %s"
                   (file-name-nondirectory (or (buffer-file-name) "?"))
                   (line-number-at-pos (or start (point)))
                   text)
          nil))

  (let ((files (or command-line-args-left '("epresent.el"))))
    (dolist (file files)
      (checkdoc-file file))
    (if (zerop epresent-checkdoc-count)
        (message "checkdoc: clean (%d file(s))" (length files))
      (message "checkdoc: %d complaint(s)" epresent-checkdoc-count)
      (kill-emacs 1)))

  (provide 'checkdoc-batch)
  ;;; checkdoc-batch.el ends here
#+end_src

* Task 3a: Make the package loadable without X11

Inserted after Task 3's first CI run. The design document assigns the X11
pointer work to P3, on the understanding that it degrades the laser-pointer
feature on non-X displays. That understanding was wrong, and CI proved it in
33 seconds:

#+begin_example
  Error: void-variable (x-pointer-dot)
    custom-declare-variable(epresent-x-pointer-shape x-pointer-dot ...)
  Symbol's value as variable is void: x-pointer-dot
  make: *** [Makefile:24: test] Error 255
#+end_example

=epresent-x-pointer-shape= defaults to the bare symbol =x-pointer-dot=, which
=defcustom= evaluates at load time. That constant is defined by =term/x-win.el=,
so on an Emacs without X the file does not merely misbehave — *it fails to load
at all*, and the package is unusable. That covers macOS and Windows builds,
terminal Emacs, and every headless CI runner. It went unnoticed locally because
this machine's Emacs is an X build, which binds the constant even under
=--batch=.

This blocks P0's exit criteria and every later task's verification, so it is
fixed here rather than in P3. P3 still owns the rest of the pointer work —
=epresent-toggle-mouse=, the save/restore of the user's pointer settings, and
the =void-text-area-pointer= handling.

- [ ] *Step 4: Declare the X variables for the compiler*

A =boundp= guard stops the runtime error but not the compiler warning, and it
suppresses the warning only for the *literal symbol it names* — so guarding on
=x-pointer-shape= leaves its siblings warning inside the very same block. That
was found the hard way: the first attempt at this task guarded all three sites
correctly and still left five =free variable= warnings on 29.4 and 30.2, which
would have failed Task 14's compile gate on code introduced here.

A valueless =defvar= marks a symbol special for this file's compilation without
binding it, which is exactly what is wanted: the compiler stops warning, and
every =boundp= check still decides correctly at runtime. Put these after the
=require= forms and before =defgroup=:

#+begin_src emacs-lisp :eval no
  ;; These exist only on X11 builds, where term/x-win.el defines them.  The
  ;; bare declarations keep the byte-compiler quiet on other builds; the
  ;; `boundp' guards at each use site are what decide anything at runtime.
  (defvar x-pointer-dot)
  (defvar x-pointer-shape)
  (defvar x-pointer-invisible)
  (defvar x-sensitive-text-pointer-shape)
#+end_src

Verify with a subprocess that has the symbols unbound, since this machine's
Emacs is an X build and binds them natively:

#+begin_src sh
  emacs -Q --batch -l test/init.el \
    --eval "(mapc #'makunbound '(x-pointer-dot x-pointer-shape \
x-pointer-invisible x-sensitive-text-pointer-shape))" \
    --eval '(byte-compile-file "epresent.el")'
#+end_src

Expected: none of the five pointer warnings. Other warnings remain — later
tasks own those.

=epresent--get-frame=, =epresent-quit= and =epresent-toggle-mouse= assign to

  (when (boundp 'x-pointer-shape)

    (setq epresent-user-x-sensitive-text-pointer-shape
          x-sensitive-text-pointer-shape)

#+begin_src emacs-lisp :eval no
  (defun epresent--collect-notes ()
    "Return this buffer's speaker notes as Org text.
Each frame-level heading contributes a first-level heading, followed by
the body of its \"Speaker notes\" subtree when it has one."
    (setq speaker-notes "")
    (save-excursion
      (goto-char (point-min))
      (while (< (point) (point-max))
        (org-next-visible-heading 1)
        (setq current-heading (org-entry-get nil "ITEM"))
        (if (= (org-current-level) 1)
            (setq speaker-notes
                  (concat speaker-notes "* " current-heading "\n")))
        (when (string= current-heading "Speaker notes")
          (org-mark-subtree)
          (setq speaker-notes
                (concat speaker-notes
                        (buffer-substring (point) (mark))
                        "\n")))))
    (deactivate-mark)
    speaker-notes)

  (defun epresent-make-notes-buffer ()
    "Collect speaker notes into a buffer and show it in a new frame."
    (interactive)
    (let ((notes (epresent--collect-notes)))
      (if (bufferp epresent-notes-buffer)
          (kill-buffer epresent-notes-buffer))
      (setq epresent-notes-buffer (generate-new-buffer "*EPresent Notes*"))
      (with-current-buffer epresent-notes-buffer
        (erase-buffer)
        (org-mode)
        (insert notes)
        (goto-char (point-min))
        (while (re-search-forward "\\*\\* ?.* Speaker [nN]otes[ \t]*\n" nil t)
          (replace-match ""))
        (goto-char (point-min))
        (org-narrow-to-subtree))
      (switch-to-buffer-other-frame epresent-notes-buffer)))

#+begin_src emacs-lisp :eval no
  (defun epresent-latex-property-drawer (blob contents _info)
    "Translate the property drawer BLOB with CONTENTS into LaTeX.
EPRESENT_VIDEO_ALT becomes a bracketed note naming the file.
EPRESENT_SHOW_FILE becomes an included Org file when it names one, and
an \\includegraphics otherwise, honouring EPRESENT_SHOW_WIDTH and
EPRESENT_SHOW_PAGES."
    (let ((input (org-export-expand blob contents t))
          (output nil))
      ;; videos are named, not embedded
      (when (string-match "EPRESENT_VIDEO_ALT:\s+\\(.+\\)" input)
        (setq output (concat output "\n[ Video: " (match-string 1 input) " ]\n\n")))
      (when (string-match "EPRESENT_SHOW_FILE:\s+\\(.+\\)" input)
        (let* ((filename (replace-regexp-in-string
                          "\\]?\\]?$" ""
                          (replace-regexp-in-string
                           "^\\[?\\[?" "" (match-string 1 input))))
               (extension (file-name-extension filename)))
          (if (string= extension "org")
              ;; Org files are converted to LaTeX and inlined.  Read the file
              ;; into a temporary buffer rather than visiting it: visiting
              ;; would hand us the user's own buffer if they have the file
              ;; open, and the conversion replaces the buffer's contents.
              (setq output
                    (concat output
                            (with-temp-buffer
                              (insert-file-contents filename)
                              (org-export-string-as (buffer-string) 'latex t))))
            ;; everything else is treated as an image
            (let ((width (if (string-match "EPRESENT_SHOW_WIDTH:\s+\\(.+\\)" input)
                             (match-string 1 input)
                           "0.5"))
                  (pages (if (string-match "EPRESENT_SHOW_PAGES:\s+\\(.+\\)" input)
                             (split-string (match-string 1 input))
                           '("1"))))
              (setq output (concat output "\n"))
              (dolist (page pages)
                (setq output
                      (concat output
                              "\\includegraphics[width=" width
                              "\\textwidth,page=" page "]{" filename "}\n")))))))
      output))
#+end_src

Two incidental fixes forced by the compiler: the =message= calls that bracketed
the function are gone (they wrote to the echo area on every drawer of every
export), and =kill-this-buffer= — a menu command that misbehaves when called
from Lisp — becomes =kill-buffer=.

The third, =mark-whole-buffer=, is the interesting one. An earlier draft of this
plan simply dropped it "in favour of =buffer-string=, which is what the
mark-and-substring dance was computing". That was wrong, and it shipped a
regression that the review caught: =mark-whole-buffer= was *also* activating the
region, and =org-latex-convert-region-to-latex= → =org-export-replace-region-by=
begins with =(unless (org-region-active-p) (user-error "No active region to
replace"))=. Without it, exporting any slide whose =EPRESENT_SHOW_FILE= names an
=.org= file aborts.

Restoring the mark would not have been right either. =org-region-active-p=
requires =transient-mark-mode=, which is nil under =--batch=, so the region
approach never worked in batch export at all. And =find-file= on a file the user
already has open returns *their* buffer, which the conversion then overwrites,
=set-buffer-modified-p nil= marks clean and =kill-buffer= discards — silently
losing unsaved work. The rewrite above avoids the region API entirely and never
touches a buffer of the user's. Verified to produce identical LaTeX.

Note the ordering trap: the =EPRESENT_SHOW_WIDTH= and =EPRESENT_SHOW_PAGES=
searches must run *after* =filename= has been bound, because each
=string-match= clobbers the match data the previous one left behind. The
=let*= above binds =filename= from the =EPRESENT_SHOW_FILE= match before any
further search happens, which is why it is =let*= and not =let=.
